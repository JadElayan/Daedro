How it works

  1. Define the conditions

    Declare the range of part mass, friction, and other conditions your controller should handle.

  2. Open a pull request

    The GitHub Action uses the Daedro CLI to test both versions with the same inputs and seeds.

  3. Replay a failure

    See which conditions failures have in common, then copy the one-line command to replay a specific case.

Prototype scope

Works now

  • Franka Panda pick-and-place in MuJoCo
  • Bring your own Python controller
  • Seeded comparisons via the CLI and GitHub Action

Not yet

  • Camera-based learned policies
  • Other robots or simulators
  • Hardware validation

Passing in simulation does not guarantee real-world safety.

The name

“Fly the middle course.”

Daedro takes its name from Daedalus, the Greek craftsman who built moving statues. His advice to Icarus was to fly between the sea and the sun. We took that idea into testing by asking what range of conditions a controller can handle.
