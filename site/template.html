What it does

  • Checks every pull request

    The old and new versions run the same seeded scenarios. If the new one breaks something, the check fails and the report lands on the PR.

  • Shows you the failure

    Side-by-side videos of each regression, old version next to new, plus a command that replays it exactly.

  • Remembers every failure

    Pin a failure, from simulation or from a real robot, and every future update is tested against it. Your test suite grows with every bug.

  • Gives each robot setup a verdict

    Ready, Review, Blocked, or Needs hardware test, with who approved what and where the update went.

  • Runs your own controller

    Point it at your Python controller, or a vision policy that uses front and wrist cameras.

  • Works with low-cost arms experimental

    SO-101, the arm used with Hugging Face LeRobot, alongside the Franka Panda.

How it works

  1. Define the conditions

    Set the task and the conditions it should handle.

  2. Open a pull request

    Test both versions with the same inputs and seeds.

  3. Replay a failure

    Copy the command for the case you want to inspect.

Prototype scope

Works now

  • Franka Panda pick-and-place in MuJoCo
  • Your own Python controller, including camera observations for vision policies
  • Pull request checks, video replays, failure library and release records
  • SO-101 support, experimental: noise-free scenarios only for now

Not yet

  • Uploading your own robot model
  • Other simulators (Isaac Lab, ManiSkill)
  • Hosted runs and team dashboards
  • Deploying to real robots, or any hardware validation

Passing in simulation does not guarantee real-world safety.
