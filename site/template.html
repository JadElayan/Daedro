How it works

  1. Declare your operating envelope

    Define the range of conditions your controller should handle, such as part mass and friction.

  2. Open a pull request

    The GitHub Action runs both versions of your controller on identical seeded scenarios using the Daedro CLI. Each pair holds the simulation conditions fixed so you can see what the controller change affected.

  3. Replay any failure

    Use the report to see where regressions cluster. Copy the one-line command for a scenario to replay it exactly.

Prototype scope

Works now

  • Franka Panda pick-and-place in MuJoCo.
  • Bring your own Python controller.
  • Seeded comparisons in CI with the Daedro CLI and GitHub Action.

Not yet

  • Camera-based learned policies.
  • Other robots or simulators.
  • Hardware validation.

Passing in simulation does not guarantee real-world safety.

The name

“Fly the middle course.”

Daedro takes its name from Daedalus, the Greek craftsman who built statues that could move. When he made wings for Icarus, he told him to fly between the sea and the sun. We borrowed the idea of giving a machine a range it can work within.
